# Nutriq audit — 7 October 2026

Scope: the whole app (onboarding, Today, logging flows, photo scan and estimates, history, coach, settings, Apple
Health, local storage, sync, Supabase functions/migrations/RLS), plus Cal AI's public material for comparison.

**How it was reviewed.** Rendered on the iPhone 18 Pro Simulator: Today, the + menu, Describe meal and the meal
editor, the discard dialog, History and Settings. **Source/tests only:** the camera (the Simulator has none), photo
estimate review (covered by widget tests), Apple Health permission flows, onboarding (the Simulator account was
already set up) and the coach. Edge cases were checked with throwaway probes and then pinned with tests.

## 2. Findings

Severity: **High** = data loss/security exposure; **Medium** = wrong data, blocked flow or inaccessible control;
**Low** = edge case or hardening.

### Fixed in this pass (each with a test that failed first)

| ID | Sev. | Area | Evidence | User impact | Fix |
|---|---|---|---|---|---|
| F1 | Medium | Describe meal | `lib/domain/meal_description.dart` `_toNumber`: "1/0 cup rice" → servings `Infinity`, "0/0" → `NaN`, "99999 cups rice" → 20.5 M kcal | Infinity/NaN can't be saved (JSON encoding fails); huge amounts are rejected by the server (`meal_items.servings` 0–100) so the meal never syncs | Parsed items must be finite, > 0, ≤ 100 servings, ≤ 5,000 kcal/serving; others are listed under **Check the amount** |
| F2 | Medium | Apple Health | `HealthController.onMealSaved` wrote a meal once; `MealLogController.deleteMeal` never touched Health | Editing a meal's amounts/time or deleting it left the old entry in Health (stale or double-counted totals) | Meal log reports before/after; Health deletes Nutriq's samples at the old time and rewrites; deletes on delete; refuses to duplicate if HealthKit says no. **Not yet checked on a device** |
| F3 | Medium | Accessibility | `Semantics(excludeSemantics: true)` around tappable widgets without `onTap`: tab bar, meal cards, Today week strip, History chart, plan tiles, USDA options | Assistive tech saw buttons with no activation action (TalkBack can't activate them; VoiceOver relies on a fallback touch) | Each node now carries its own tap action (pinned by tests) |
| F4 | Low | Coach function | `supabase/functions/coach/index.ts` read and buffered the whole body before checking sign-in | Unauthenticated callers could make the function buffer large bodies | Sign-in first; body read as a stream with a byte cap (same as `scan-photo`) |
| F5 | Low | Photo estimates | `EstimatedFood.toItem` made one serving of any size (stepper allows 2,000 g) | e.g. 2,000 g of oil = 17,680 kcal in one serving → server rejects → meal never syncs | Large amounts become equal servings (4 × 500 g) |
| F6 | — | Working tree | Before this pass, `lib/features/shell/home_shell.dart` and `supabase/functions/coach/index.ts` were reset to the last commit and `tool/photo_eval.dart` + `docs/PHOTO_ESTIMATE_EVALUATION.md` were deleted (not by this pass) | The Android "Take photo" honesty label was lost; a test broke | Restored with the owner's OK; the evaluation files were re-created |

### Open — risks and gaps (not changed here)

| ID | Sev. | Area | Evidence | Impact | Proposed fix |
|---|---|---|---|---|---|
| O1 | Low (risk) | Account deletion | `supabase/functions/delete-account/index.ts` reads only `SUPABASE_SERVICE_ROLE_KEY` | If legacy API keys are ever disabled, "Delete account" stops working | Fall back to `SUPABASE_SECRET_KEYS` like `scan-photo`'s `pickKey` (needs a redeploy; the file imports remote modules so it isn't unit-tested here) |
| O2 | Low | Accessibility | `lib/app/nutriq_app.dart`: `MediaQuery.withClampedTextScaling(maxScaleFactor: 1.35)` | People who set very large text get less than they asked for | Raise/remove the cap screen by screen after layout checks at accessibility sizes |
| O3 | Low | Apple Health | "Delete all data" and meals deleted on another device (via sync) don't remove Nutriq's Health entries | Those entries stay in Health | Decide the desired behaviour; then call `HealthService.deleteMeal` there too |
| O4 | Medium (process) | Deployment | `scan-photo` and `coach` changed since the last deploy | Live functions don't have the newest checks | Redeploy (owner's action) |
| O5 | Low | Data | Some catalog aliases are approximations (bistek → beef steak; menudo/afritada/caldereta share one entry) | Values approximate for those dishes | Licensed Filipino data (see §4) |
| O6 | Low | Feature parity | Light mode only (`themeMode: ThemeMode.light`) | Glare at night | Dark tokens exist conceptually; needs a colour audit |

Checked and found sound: calories = per-serving × servings with invalid servings guarded; catalog portion maths;
local timezone handling (UTC in the cloud, `.toLocal()` on read); logical-day boundaries (field arithmetic, DST-safe);
streaks; sync push/pull with stale-write conflicts kept visible; RLS isolation and allowance functions (SQL suites);
consent before any photo upload; secrets only in function environments; Reduce Motion respected by every custom
animation; the manual food form's limits match the server's (≤ 5,000 kcal).

## 3. Design review (rendered + source)

- **Today:** clear hierarchy — calorie ring card, macro rings, scanning drafts, then meals; the floating + is the
  obvious primary action. Week strip is readable and labelled for VoiceOver (now activatable too).
- **Logging:** the + menu's four large tiles are clear; the editor's cards, steppers and native Cupertino alerts feel
  at home on iOS. Content scrolls under an opaque header without a scroll-edge fade — cosmetic.
- **History:** streak and average cards plus the weekly chart with the goal range read well; bars scale to the goal,
  so small days look small, which is honest.
- **Motion:** spring sheets and the + menu spring are restrained and fall back to fades with Reduce Motion.
- **Gaps:** Dynamic Type capped (O2); no dark mode (O6).

## 5. Accuracy

Unchanged policy: photo output stays an estimate the person reviews; no model switch or accuracy claim without a
controlled comparison. The method, CSV template and scorer are in `docs/PHOTO_ESTIMATE_EVALUATION.md` and
`tool/photo_eval.dart` (food precision/recall, missed and false foods, gram error, meal kcal/protein error and bias,
per category: simple / mixed / Filipino). **No labelled meals exist yet; nothing has been measured.**
